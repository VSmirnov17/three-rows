# Браузерные проверки (Playwright)

`run.js` проходит 33 сценария в Firefox (главный браузер игрока), WebKit (вместо Safari) и Chromium. Среди них: первый запуск и пролог, уровни на всех сложностях, лианы, проигрыш по времени, перенос старого сохранения, перенос прогресса кодом, порядок сцен в конце главы и раскладка на четырёх окнах: 1366×768, 1366×650, 390×844 и 360×740 (кнопки не меньше 56px, страница не уходит вбок). Звук выключен: флажок игры `sun-treasures-muted` плюс заглушение в самом браузере.

Игровой экран «Обсидиан и огонь» проверяется так:

- «Спокойно»: на табличке времени знак `∞`, у `body` нет `data-urgency`.
- На десктопе круг Солнечного Камня состоит ровно из 20 секторов. После победы на уровне 1-01 первый сектор заполнен (каменный осколок), не `empty`.
- Большой счёт `1 234 567` (через `__SUN.setScore`) виден целиком: текст полный, `scrollWidth <= clientWidth`, табличка не вылезает за окно. Проверяется на всех четырёх окнах.
- При 1366×650 игровой экран не прокручивается по вертикали.
- В проверке `file://` шрифт Philosopher (кириллица) загружается с диска. Там же грузятся лист огня (фон `.fire-calm` и `.fire-flare`: `new Image()` с тем же URL даёт `naturalWidth > 0`) и картинка чаши жаровни.

Жаровни и огонь (`?debug` даёт `window.__FIRE`):

- «9 braziers» на восьми окнах (1366×768, 1366×721, 1366×650, 1366×640, 1366×600, 1024×768, 390×844, 360×740): на десктопе при высоте от 640 видны ровно две `.brazier`, при 600 жаровни выключены (`body[data-braziers="off"]`, видимых нет), на телефоне их нет; `.fire-light` и `.fire-sparks` есть везде. У жаровни `aria-hidden="true"` и `pointer-events: none`. Пламя не заходит больше чем на 2px на кнопки, таблички, цели и поле, чаша не заходит ни на что, кроме таблички прямо под ней (так задумано). Полоса подсказки `#hintBar` не заходит на кнопки правой колонки и на содержимое левой (круг Солнечного Камня на узком окне 1024×768), её текст не обрезан. Кнопки не ниже 56px, на десктопных окнах нет прокрутки ни вбок, ни вниз.
- «10 fire reacts»: на стартовом экране за 1с `__FIRE.frames` не растёт, на уровне растёт. После `sun:match` с цепочкой 5 `data-flare` появляется за 300мс, свет не ярче 0,55, пламя не растёт больше чем на 22%, искры летят, через 2,2с `data-flare` нет. При открытии паузы вспышка и искры гаснут (`sparks === 0`, `data-flare` снят, цикл стоит).
- «11 prefers-reduced-motion» (контекст с `reducedMotion: 'reduce'`): цикл огня стоит, искр нет (холст пуст), вспышки нет. Живой фон в режиме `data-bd="still"`: холст светлячков пуст, у струй воды `animation-name: none`.
- В сценариях про огонь стоит `localStorage['sun-keeper-fx'] = 'full'`, чтобы медленный headless не включил слабый режим (без искр) сам.

Живой фон (земля 1 с водопадом, земля 2 без воды; `?debug` даёт `window.__BD`: `frames`, `mode`, `flies()`, `busy()`):

- «12 backdrop» на пяти окнах (1366×768, 1366×650, 1920×1080, 1024×768, 390×844), уровень 1-01. У `.bd-stage`, `.bd-sky` и `.bd-flies` есть `aria-hidden="true"` и вычисленный `pointer-events: none`. На стартовом экране `data-bd="paused"`: за 1с `__BD.frames` не растёт, у `.bd-water` `animation-play-state: paused`. На уровне `run`, кадры идут. На 390×844 `still`, у `.bd-water` `animation-name: none`, светлячков нет.
- Видимость луны и водопада. Слои фона `pointer-events: none`, а `.game-shell` занимает всё окно. Поэтому точку проверяют через `document.elementsFromPoint` сверху вниз: прозрачные обёртки пропускаются, точку закрывает первый элемент, который что-то рисует (фон, рамка, картинка, кнопка, текст), и чаша жаровни (по её прямоугольнику). Точка открыта, если раньше попался элемент внутри `.jungle`. Луна: сетка 7×7 по рамке `.bd-moon`, открыто не меньше 60% при 1366×768, 1366×650 и 1920×1080. Водопад: 20 точек по средней вертикали `.bd-wf`, открыто не меньше 25% при 1366×768 и 1920×1080. На остальных окнах доля только пишется в отчёт.
- Светлячки: через 2с все `__BD.flies()` дальше 10px от `__BD.busy()` и от свежих прямоугольников табличек, кнопок, рамки поля, жаровен, круга Камня с подписью земли и подсказки. Список занятых мест берётся у игры (`__BD.busySelector`), копии в `run.js` нет. На десктопе светлячков должно быть больше нуля, иначе проверка прошла бы вхолостую. То же через 1с после `page.setViewportSize` на другое окно.
- «12 backdrop land switch»: после победы на 1-01 клетка мозаики на карте по-прежнему `bg-jaguar.webp`. После `__SUN.start('2-01')` слой `[data-theme="1"]` без `.on`, `body.has-backdrop` включён, в слое земли 2 есть `.bd-stage`, луна и облака, но нет `.bd-wf`, `.bd-mist`, `.bd-water`; плита `assets/backdrop/land2/plate.webp` (1672 px) загружена; режим `run`, кадры светлячков идут, они не над табличками, кнопками и рамкой поля; луна открыта не меньше чем на 60 %; ошибок консоли нет.
- В проверке `file://` пять картинок фона земли 1 (`plate`, `water`, `mask`, `moon`, `clouds` из `Campaign`) и три картинки земли 2 (`plate`, `moon`, `clouds`; воды у неё нет) грузятся через `new Image()`. Маска `.bd-wf` задана и это `data:` URI из `assets/backdrop/land1/water-mask.js`, ошибок загрузки `assets/backdrop/` нет. CSS-маску по `file://` Chromium и WebKit грузят с CORS и не отдают, поэтому маска встроена в скрипт.

Эффекты поля (`js/visuals-fx.js`, `window.Fx`):

- «13 strikes» (1366×768, уровень 1-01 на «Обычно», `sun-keeper-fx = 'full'`): после обычного хода первый `.fx-shard` в `#fx` появляется не позже 150 мс после того, как камень спрятан (`fx-gone`), каждый осколок живёт не дольше 700 мс, через 700 мс после хода нет ни `.fx-shard`, ни `.fx-standin`, через 1,5 с `Fx.particles() === 0`. Лианы: `__SUN.setVines([[3,5]])`, `__SUN.strike(3, 1, 'line', 'row')` — камень (3,5) получил `vine-snap`, его узел жив, осколков у клетки (3,5) не было, а в ряду 3 были. За весь сценарий `.blast-flash` не появлялся, у `.board-frame` не было `blast`/`blast-sun`; ошибок консоли нет.

Playwright ставится **вне проекта**, у игры зависимостей нет:

```bash
mkdir -p /tmp/pw && cd /tmp/pw && npm init -y && npm i playwright && npx playwright install firefox webkit chromium
# из корня игры:
python3 -m http.server 8775 &
NODE_PATH=/tmp/pw/node_modules node tools/e2e/run.js
```

Правила запуска:

- Каждый сценарий закрывает за собой все страницы, которые открыл, даже если упал (`scenario()` в `run.js`). Упавшая проверка не оставляет живую страницу с огнём и фоном.
- При отладке запускать один браузер и `ONLY=<часть названия>`. Полный набор во всех трёх браузерах сильно грузит компьютер: только в конце работы.

- Запускать один процесс `run.js` за раз. Браузеры по аргументу (`firefox`, `webkit`, `chromium`) параллельно не запускать. Без аргумента `node run.js` сам проходит их по очереди.
- `python3 -m http.server` может обрывать соединения под нагрузкой (`ERR_CONNECTION_RESET`). Если это случилось, перезапустить прогон этого браузера. Сервер к `run.js` не привязан, его запускают отдельно, как выше.
- Код выхода `run.js` равен 0, если все сценарии прошли, и 1, если упал хотя бы один.

Скриншоты и `results-*.json` пишутся в `$E2E_OUT` (по умолчанию `<tmp>/hranitel-e2e`). Корень игры задаёт `GAME_ROOT`, порт задаёт `PORT`.
