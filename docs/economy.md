# Экономика очков «Сокровища Солнца»

Документ описывает новую формулу, константы, симуляцию и точный патч
интеграции в `js/game.js`. Код экономики живёт в `js/economy.js`,
симулятор — в `tools/economy-sim.js`.

---

## 1. В чём была проблема

Старая формула в `js/game.js`:

```js
// за каждый каскад
const mult = Math.min(8, chain + 1);
const gained = Math.round(clear.size * 20 * mult + creates.length * 40);

// при победе
const bonus = Math.floor(state.timeLeft) * 10;
```

Очки за очистку зависели только от числа клеток и каскада. Игрок, который
не спешит, успевает сделать больше ходов и очистить больше камней, а
бонус за остаток времени (10 очков за секунду) не покрывает разницу.

Симулятор считает ту же модель быстрого и медленного игрока по старой
формуле:

| Уровень | Быстрый | Медленный | Быстрый к медленному |
|---|---:|---:|---:|
| Тропа Ягуара | 4 995 | 10 830 | **−53,9%** |
| Храм Пернатого Змея | 4 500 | 10 905 | **−58,7%** |
| Пещера Лунного Света | 6 750 | 12 245 | **−44,9%** |
| Золотое Солнце | 5 792 | 12 932 | **−55,2%** |

То есть быстрый проход проигрывал почти вдвое. Бонус времени был не
наградой за скорость, а слабой компенсацией за пропущенные ходы.

---

## 2. Новая формула

### 2.1. Очки за один каскад

```
frac      = timeLeft / totalTime                 // доля оставшегося времени
chainMult = min(8, 1 + chain)                    // ×2…×8, как в старом UI
pace      = 0.25 + (3.2 − 0.25) · frac²           // «темп», ×0.25…×3.2

cellPoints  = cells · 1.5
goalPoints  = goalCells · 15
pattern     = сумма наград за creates и triggers
raw         = (cellPoints + goalPoints + pattern) · chainMult
score       = round(raw · pace)
```

Ключевые отличия:

1. **`goalCells`** — клетки цветов, которые ещё нужны целям. Обычная
   клетка даёт 1,5 очка, целевая — 16,5 (1,5 + 15). Поэтому «фарм»
   пустых камней почти не приносит очков, а закрытие целей — приносит.
2. **`pace`** — главный множитель за скорость. Считается по времени на
   момент хода, а не по времени в конце. Ранний ход стоит в разы дороже
   позднего.
3. **Каскад** по-прежнему умножает всё: `chain = 1 → ×2`, `chain = 2 → ×3`,
   … `chain ≥ 7 → ×8`. Это совпадает с лестницей комбо в интерфейсе.
4. **Паттерны** дают отдельную награду за создание спецкамня и за его
   срабатывание, поэтому линия 4 всегда выгоднее тройки.

### 2.2. Бонус за завершение

```
bonus = round(8 · timeLeft · (1 − 0.5 · frac))
```

Это маленький бонус: максимум 8 очков за секунду остатка, причём каждая
следующая сэкономленная секунда стоит чуть меньше (функция вогнутая).
Для быстрого прохода это 400–500 очков, для
«досиживания» с 5 секундами — ~15. Один нормальный ход стоит больше,
поэтому тянуть время невыгодно.

### 2.3. Ранг скорости

Ранг не зависит от очков и считается по доле использованного времени:

| Использовано времени | Звёзды | Ранг |
|---|---|---|
| ≤ 50% | ★★★ | Молниеносно |
| ≤ 75% | ★★☆ | Быстро |
| > 75% | ★☆☆ | Неспешно |

## 3. Как читать темп в UI

`Economy.paceAt(frac)` возвращает множитель, `Economy.formatPace(mult)` —
готовую строку вида `×1,84`.

| Осталось времени | Темп |
|---|---:|
| 100% | ×3,20 |
| 75% | ×1,91 |
| 50% | ×0,99 |
| 25% | ×0,43 |
| 0% | ×0,25 |

Что показывать игроку:

- **во время хода** — всплывающие `+540 · темп ×2,31` над полем
  (патч ниже добавляет `econ.paceLabel` в существующий `spawnScoreFloat`);
- **на экране победы** — средний темп за уровень
  (`clearScore / base`) и ранг: `★★★ Молниеносно`;
- **в подсказке/бейдже** — при желании `Economy.formatPace(...)` можно
  выводить в `dom.comboBadge` или `dom.hintBar`; отдельная вёрстка не
  нужна.

Смысл для игрока простой: «пока таймер полный — каждый камень дороже».
К концу уровня темп падает до ×0,25, поэтому досиживание обесценивает
именно те ходы, которые закрывают цели.

### Шаг 4. Считать очки каскада через `Economy`

`resolveBoard`, заменить строки 1193–1198:

```js
      const gained = Math.round(clear.size * 20 * mult + creates.length * 40);
      setScore(state.score + gained, true);

      const cellsArr = Array.from(clear).map(parseKey);
      let sr = 0;
      let sc = 0;
```

на:

```js
      const cellsArr = Array.from(clear).map(parseKey);

      // Клетки, которые реально двигают незакрытые цели.
      // Считаем по остатку need для каждого цвета, чтобы последний
      // каскад не получал бонус за «перебор» сверх цели.
      const needLeft = new Map();
      state.goals.forEach(g => {
        if (g.got < g.need) needLeft.set(g.color, g.need - g.got);
      });
      let goalCells = 0;
      cellsArr.forEach(p => {
        const gem = gemAt(p.r, p.c);
        if (!gem) return;
        const left = needLeft.get(gem.color) || 0;
        if (left > 0) {
          goalCells++;
          needLeft.set(gem.color, left - 1);
        }
      });

      const econ = Economy.clearDetail({
        cells: clear.size,
        goalCells: goalCells,
        chain: chain,
        creates: creates,     // [{ type: 'line'|'sun'|'bomb'|'totem' }]
        triggers: triggers,   // [{ type: 'line'|'sun'|'bomb'|'totem' }]
        timeLeft: state.timeLeft,
        totalTime: state.totalTime
      });

      const gained = econ.score;
      state.econBase += econ.raw;   // raw уже с каскадным множителем
      state.econClear += econ.score;
      setScore(state.score + gained, true);

      let sr = 0;
      let sc = 0;
```

`mult` остаётся для `setCombo` и подписи; `Economy` использует ту же
формулу `min(8, 1 + chain)`, поэтому расхождений с лестницей комбо нет.

## 7. Почему «досиживание» больше не выгодно

- Бонус за секунду остатка не превышает 8 очков и падает с ростом
  остатка; один ход стоит десятки-сотни очков.
- Дополнительные «пустые» ходы дают только `CELL_POINTS` (1,5 за клетку)
  без целевой надбавки. Чтобы дожить до конца, игрок вынужден отложить
  закрытие целей, а каждая отложенная целевая клетка теряет темп:
  на 50% времени множитель ×0,99, на 20% — уже ×0,37.
- В симуляции медленный игрок делает в 2–3 раза больше ходов, но
  проигрывает 25–43% именно из-за темпа.
