# Этап 3, земля 4 «Горная тропа»: валуны — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Землю 4 можно пройти в игре. Валуны стоят на поле, трескаются от рядов рядом и от ударов спецкамней, считаются в целях. Все 20 уровней проходимы ботом на трёх сложностях. У земли свой фон, и небо на нём уже предрассветное: это первый шаг «рассвета по землям».

**Architecture:** Валун — отдельный слой клеток `boulders[r][c] = прочность` (0 — пусто), как золотые плиты. В сетке камней на клетке валуна `null`. Чистое ядро (`js/core/board.js`) знает валуны в трёх местах: новое поле оставляет их клетки пустыми, обрушение проводит камни сквозь них (как сквозь камни в лианах) и не досыпает туда новых, а `hitBoulders` снимает прочность. Бот и игра зовут те же функции. Вид валуна — спрайт Codex с трещинами по прочности, слой `#boulders` поверх камней.

**Tech Stack:** ванильный JS без сборки (работает с `file://`), CSS-анимации `transform`/`opacity`; Node `node:test`; Playwright вне проекта (`tools/e2e/run.js`); Codex для арта.

**Spec:** `docs/superpowers/specs/2026-11-06-hranitel-solnca-design.md`: §5 (земля 4, валуны; каждая земля сохраняет прошлые механики), §6, §8 (живые фоны, рассвет по землям), §10 (бот-проверка), §11 п.3. Образец предыдущей земли — `docs/superpowers/plans/2026-11-14-phase3-land3-plates.md`. Правила проекта — `docs/superpowers/STATUS.md`, «Правила работы».

## Правило валуна (решения, принятые без пользователя)

- Валун занимает клетку. Его нельзя двигать, менять местами и выбирать. Попытка обмена с валуном даёт тот же мягкий отказ, что и лиана (`refuseLocked`), ход не тратится.
- Камни падают **сквозь** валун, как сквозь камень в лианах: клетка валуна в обрушении не свободна и не досыпается, камни выше неё уходят в свободные клетки ниже. Иначе клетки под валуном навсегда остались бы пустыми.
- Удар: за один шаг каскада валун теряет **не больше 1** прочности, если (а) его клетку накрыл удар спецкамня (клетка есть в `plan.clear`) или (б) соседняя по стороне клетка, не валун, есть в `plan.clear`, `plan.unlocks` или `plan.creates`. Солнце бьёт камни своего цвета, валун у него цвета нет: солнце бьёт валун только через соседство, как обычный ряд.
- Прочность 1–3 («крепкие держат 2–3 удара», §5). При 0 клетка становится свободной, и ближайшее обрушение её досыпает.
- Цель `{ type: 'boulders', need }`, где `need` — число валунов, а не сумма прочности: «Валуны 2 / 6» понятнее. Валун засчитан, когда разбит до конца.
- Очков валун не даёт и в `goalCells`/экономику не входит, как плиты. Клетки без камня, накрытые ударом спецкамня, ядро убирает из `plan.clear` в отдельный список `plan.voids` (конец `expandSpecials`). Иначе бот сломается: `runMove` режет `removed` по `plan.clear.size` и бросает ошибку при расхождении (`tools/level-bot.js:127-166`), а игра добавила бы очки за клетку валуна (`playStep`, `cells: clear.size`). Поправка одна, в ядре, и видна обоим. На землях 1–3 она ничего не меняет: при планировании каскада поле всегда полное.
- Валун не ставится на клетку с плитой или лианой (проверка данных в `Campaign.validate`).
- Начиная с земли 4 уровни сочетают валуны с прошлыми механиками: лианы с 4-07, плиты с 4-11.

## Review Focus

1. **Обрушение сквозь валун:** в столбце с валуном камни не попадают в его клетку, новые там не рождаются, под валуном нет пустых клеток. Тест ядра — задача 1.
2. **Разбитый валун досыпается** тем же шагом каскада: после хода на поле нет `null`, кроме живых валунов. Тест ядра — задача 1, e2e — задача 5.
3. **Не больше одного удара за шаг:** ряд из пяти камней вдоль валуна снимает 1 прочность, а не 5. Тест ядра.
4. **Земли 1–3 не задеты:** `collapse` без валунов работает как раньше (старые тесты ядра без правок), бот на землях 1–3 проходит.
5. **Перемешивание** не трогает валуны и не ставит камни на их клетки.
6. **Очки:** удар бомбы по валуну не добавляет очков за его клетку.

**Interfaces (Produces):**
- `makeBoulders(list) -> number[8][8]`, где `list` — `[[r, c, hp], …]` (без `hp` — 1).
- `bouldersLeft(boulders) -> number` — сколько валунов ещё стоит (клеток с прочностью > 0).
- `expandSpecials`/`planCascade`: ключи клеток без камня уходят из `clear` в `voids: Set<'r,c'>` (в плане всегда есть, может быть пустым).
- `hitBoulders(boulders, plan) -> [{ r, c, left }]` — правило удара выше: прямой удар — клетка валуна в `plan.voids`, соседство — от клеток `clear`, `unlocks`, `creates`. Меняет `boulders`.
- `collapse(grid, spawn, blocked)` — необязательный `blocked(r, c) -> bool`: клетка не свободна и не движется, камни проходят сквозь неё. Без третьего аргумента всё как раньше.
- `generateGrid(level, …)`: `level.boulders` (`[[r, c, hp], …]`) оставляет эти клетки `null`. Запреты на начальные совпадения уже пропускают `null`.
- `simulateMove(grid, a, b, rng, nextId, opts)`: `opts.boulders` — слой. На каждом шаге каскада ядро зовёт `hitBoulders` до обрушения, и обрушение получает `blocked` по слою. В результат добавляется `boulderHits: [{ r, c, left }]`.
- `shuffle` правок не требует (пропускает `null`), но тест это закрепляет.
