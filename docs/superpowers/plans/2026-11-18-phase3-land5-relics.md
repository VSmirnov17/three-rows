# Этап 3, земля 5 «Озёрный город»: реликвии — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Землю 5 можно пройти в игре. Золотые идолы стоят на поле, падают вместе с камнями и засчитываются, когда опустятся на дно поля. Все 20 уровней проходимы ботом на трёх сложностях. У земли свой фон, небо светлее, чем у земли 4 (второй шаг рассвета).

**Architecture:** Идол — особый «камень» в той же сетке: `{ relic: true, color: -1, special: null, locked: false }`. Он падает и меняется местами, как камень, но не входит в совпадения и не убирается ударами. Ядро (`js/core/board.js`) знает идолов в четырёх местах: поиск серий и квадратов их пропускает, `expandSpecials` выкидывает их клетки из `clear`, `shuffle` их не двигает, `collectRelics` снимает идолов с нижней строки. `simulateMove` после каждого обрушения снимает идолов и досыпает поле. Бот и игра зовут те же функции. Вид — спрайт Codex.

**Tech Stack:** ванильный JS без сборки (работает с `file://`), CSS-анимации `transform`/`opacity`; Node `node:test`; Playwright вне проекта (`tools/e2e/run.js`); Codex для арта.

**Spec:** `docs/superpowers/specs/2026-11-06-hranitel-solnca-design.md`: §5 (земля 5, реликвии; прошлые механики сохраняются), §8 (рассвет по землям), §10 (бот), §11 п.3. Образец — `docs/superpowers/plans/2026-11-18-phase3-land4-boulders.md`.

## Правило идола (решения, принятые без пользователя)

- Идол занимает клетку сетки. Его **можно** менять местами с соседним камнем, если сам камень после обмена собирает ряд (как ингредиенты в похожих играх). Отдельного отказа не нужно: обмен без ряда и так отменяется.
- Идол падает, как камень, в том числе сквозь валуны и камни в лианах.
- Идол не собирается в ряды: два-три идола рядом — не совпадение. Удары спецкамней его не разбивают, солнце его не берёт (у идола нет цвета). Идол в зоне удара не трескает соседние валуны и не снимает плиту под собой.
- **Сбор:** идол, оказавшийся в нижней строке (`r = 7`), снимается с поля и засчитывается. Его клетка досыпается тем же шагом. Если внизу столбца валун или камень в лианах, идол ждёт над ним, пока путь не освободится.
- Все идолы стоят на поле с начала уровня (обычно в верхних строках). Новые сверху не падают. Цель `{ type: 'relics', need }`: `need` — число идолов. В чипе цели — «Идолы N / M».
- Очков идол не даёт (как плиты и валуны).
- Слово для игрока: механика — «реликвии», на поле это золотые идолы. Чип — «Идолы», вступительная сцена связывает: «реликвии — золотые идолы».
- Живой элемент земли (рябь на воде, §8) отложен до «да» на фон; облака общие с землёй 1, как у земли 4.
- Проверка данных: идол не на валуне, не на лиане (и с клетками «Испытания»), не в нижней строке.
- Уровни земли 5 сочетают идолов с прошлыми механиками: валуны с 5-06, лианы с 5-09, плиты с 5-12.

- Без сборки и npm-зависимостей у игры, работает и с хостинга, и с `file://`.
- Тексты UI — HTML поверх текстур, надписи в картинки не впекать.
- Анимировать только `transform` и `opacity`.
- Перед серией картинок — 1–2 образца и «да» пользователя. Движение показывать живьём на локальном сервере.
- Земли 1–4 не меняются: после правок ядра `node tools/level-bot.js --check --lands 1-4` проходит, как раньше.
- Полный набор e2e — один раз в конце. При отладке `ONLY=` и один браузер (Firefox). Не оставлять висящих headless и `http.server`.
- Не выкладывать и не пушить без прямой просьбы. Коммиты без подписей.

## Review Focus

1. **Идол не совпадает:** три идола в ряд или квадрат из идолов не дают совпадения; идол в середине ряда разрывает его.
2. **Удары не трогают идола:** бомба, молния, тотем и солнце рядом с идолом оставляют его на месте; `clear` его не содержит, `removed` бота сходится с `clear.size`.
3. **Сбор:** идол в нижней строке снимается после обрушения, клетка досыпается, на поле нет `null`, кроме живых валунов. Идол над валуном в нижней строке не снимается.
4. **Перемешивание** не двигает идолов и не перекрашивает их.
5. **Земли 1–4 не задеты:** без идолов всё как раньше (старые тесты ядра без правок, бот).

### Task 1: Идолы в ядре поля

**Files:** `js/core/board.js`, `tests/board-core.test.js`

**Interfaces (Produces):**
- `findLineGroups`, `findSquares`: идол (`gem.relic`) разрывает серию и не входит в квадрат.
- `expandSpecials`: клетки идолов уходят из `clear` (не в `voids` и не в `unlocks`).
- `shuffle`: идолы не двигаются и не перекрашиваются.
- `generateGrid(level, …)`: `level.relics` (`[[r, c], …]`) ставит идолов.
- `makeRelic(id, r, c) -> gem`.
- `collectRelics(grid) -> gem[]`: снимает идолов с нижней строки (клетка → `null`).
- `relicsLeft(grid) -> number`.
- `settle(grid, spawn, blocked) -> { moves, spawned, relics }`: `collapse`, затем, пока `collectRelics` что-то снимает, снова `collapse` (два идола друг над другом снимаются оба). Зовут и `simulateMove`, и `dropGems` игры. В результат `simulateMove` — `relics: gem[]` (снятые), в `removed` они не входят.
- Идол узнаётся только по флагу `relic`, не по цвету: запасной путь `shuffle` временно даёт камням цвета `-1, -2, …`.
