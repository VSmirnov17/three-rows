## obsidian.webp — бесшовность
Codex дал 1254×1254 с трещинами, обрезанными по краям. Сделал бесшовным сам: взял 1024×1024, по каждой оси перекрёстное растворение (smoothstep, перекрытие 230 px) начала тайла с его продолжением — тайл периодичен. Затем 512×512 (LANCZOS). Проверка: склейка 2×2 с усилением яркости ×6/×8, стыков не видно; средний скачок через границу 0.60/0.71 против 0.55 между соседними пикселями. Трещины в 2×2 повторяются (видно только при усилении яркости).

## panel-frame.webp — `border-image`
Codex сгенерировал рамку с однородным меандром по сторонам и украшениями (заклёпка + квадратная нефритовая вставка) только в углах. Дальше пересобрал картинку: внешнее поле и внутренняя зона (обсидиан) прозрачны; углы взяты из исходника как есть, боковые полосы — один повторяющийся тайл (4 периода меандра, концы сведены растворением 50 px, поэтому `round` не даёт швов); в картинке нет лишнего, середина (центр) прозрачна. Нижняя кромка углов и тайлов взяты с запасом из прозрачного поля, чтобы Firefox не «подмешивал» соседнюю строку золота (был волосок на стыке тайлов).

`border-image-slice` (px картинки 418×355): **верх 58, право 83, низ 58, лево 89** (без `fill`).
Рекомендация: `border-image-repeat: round`. Рабочий пример (проверен в Firefox, `series-preview.html`):
```css
border: 18px solid transparent;           /* раскладка */
border-image: url(../assets/ui/panel-frame.webp) 58 83 58 89 / 18px 27px 18px 29px round;
background: url(../assets/ui/obsidian.webp) 0 0 / 256px;   /* заливка под рамкой, border-box */
```
Ширины 27/29 px по бокам больше раскладочных 18 px: углы с нефритом шире, чем полоса (масштаб 18/58 везде одинаков); лишние 8–11 px лежат на прозрачной внутренней полосе картинки и не мешают тексту.

## btn-plate.webp — `border-image ... fill`
Плита обсидиан, тонкая золотая кромка (после правки около 2.4% высоты; Codex дал 1.6%, утолщена копиями кольца, сдвинутыми внутрь на 4 px при полном размере), скруглённые углы, без свечения и меандра. Внутренность приглушена (множитель 0.5 вне золота), чтобы блики и трещины не спорили с текстом.

`border-image-slice`: **20** со всех сторон, с `fill`. Рекомендация: `border-image: url(../assets/ui/btn-plate.webp) 20 fill / 14px stretch; border: 14px solid transparent;` (кнопка 300×72: золото ≈ 3 px; при 56 px высоты ≈ 2.5 px).

## board-frame-gold.webp
Золотой меандр, квадратные нефритовые вставки в серединах сторон, заклёпки в углах. Центр и внешнее поле прозрачны. Толщина полосы ≈ **8.3 % ширины** (лево 8.3, право 8.1, верх 8.1, низ 8.4). Использовать как фон растянутым, как сейчас старая рамка (`styles.css:899`, `background: url(...) center / 100% 100%`), с внутренним отступом ≈ **8.4 %**; через `border-image` не резать — вставки в серединах сторон ломаются. Картинка почти квадратная (900×898).

## Сборка

`python3 tools/pack_backdrop.py --land 1` (только Pillow) кладёт в `assets/backdrop/land1/`:

- `plate.webp` — плита как есть, q 86.
- `water-mask.webp` — где вода видна. Вырезка плиты x 20–170, y 0–905; яркость, размытая на 10 px, `(L−45)/40`, умноженная на синеву `(B−R+5)/30`, потом размытие 6 px и затухание сверху на 40 px, снизу на 60 px, слева и справа — по 15 % ширины (smoothstep), а два крайних столбца с каждой стороны ровно 0. Без боковых затуханий маска у тумана внизу упиралась в край вырезки, и на экране была прямая вертикальная линия; `--check` проверяет нули по краям. Хранится в **альфа**-канале белой картинки WebP lossless: CSS `mask` по умолчанию берёт альфу, серая картинка без альфы ничего не маскирует.
- `water-mask.js` — та же маска как `data:` URI в `window.BACKDROP_DATA['assets/backdrop/land1/water-mask.webp']`, пишется из готового `water-mask.webp`. CSS-маску с `file://` Chromium и WebKit не грузят (запрос маски идёт с CORS), поэтому игра берёт маску отсюда; `tests/backdrop-core.test.js` сверяет байты с `.webp`.
- `water.webp` — плитка «струй», RGBA. Кусок вырезки y 150–750, «высокие частоты» `(s − blur7(s))·2.2 + 8`; их яркость L даёт альфу `clip((L − 12)/90, 0, 1)·255`, цвет ровный бело-голубой (215, 232, 245). Слой только светлит: тёмные места прозрачны. Прежняя RGB-плитка без альфы затемняла нарисованный водопад, потому что маска делает `.bd-wf` изолированной группой и `mix-blend-mode: screen` там работает как обычное наложение; теперь смешивания нет. Растяжение по вертикали ×1,3 и бесшовность (последние 120 строк плавно переходят в первые 120, которые отбрасываются) делаются на альфе. Итог 150×660, плитка = 660/941 высоты плиты. `--check` проверяет, что файл RGBA.
- `moon.webp` — 256×256, круглая альфа (суперсэмплинг ×4, отступ 1,5 px). Вшиты `brightness(.92)` и размытие (в пробнике CSS `blur(.6px)` шёл по диску около 100 px, на картинке 256 px это около 1,5 px). Непрозрачность 0,8 — в CSS.
- `clouds.webp` — вдвое меньше исходника, 1086×362. Альфа = `max(R,G,B)`, нормированная к 99,9-му процентилю, со степенью 0,8; цвет постоянный бледно-серо-голубой (190, 205, 225). (Пробник делил цвет на максимум канала; в плане решено иначе.)
- `backdrop.json` — размеры и геометрия воды; правда для CSS и JS.

Скрипт печатает размеры файлов (бюджет 450 КБ на все) и числа шва струй, и собирает лист проверки `backdrop/check.png` (маска, две копии плитки одна над другой, луна и облака на `#0d1b2e`).

# Шаг 5 — раскол камней и удары спецкамней (образец 1: раскол и бомба — «Да, берём»; образец 2: молния, солнце, тотем — «Да, берём»)

Образец 1 (утверждён: «Да, берём» — раскол камней и бомба): `strikes/sample1.webm` (Chromium, 1366×768, 13,5 с: три обычных хода, бомба в центре поля, затем бомба на «Спокойно»; загрузка и отсчёт «3, 2, 1» вырезаны). Запись — `tools/record-fx.js`: headless-Firefox в Playwright пишет в видео только изменившиеся куски экрана (неподвижное оставалось чёрным), поэтому видео пишет Chromium; кадры и e2e — Firefox.

## Источник

Готовая симуляция **EmberGen «Ground Explosion»** из бесплатного набора JangaFX — https://jangafx.com/software/embergen/download/free-vdb-animations/ (архив `GroundExplosionVDB.zip`, 200 кадров VDB `ground_explosion_0000…0199.vdb`, поля `density` и `flames`, около 1,2 ГБ; лицензия **CC0 — Public Domain**, «Created with EmberGen by JangaFX», `assets/fx/LICENSE-EmberGen-CC0.txt`). VDB в git нет, лежат вне проекта.

## Рендер (`blender/explosion_vdb.py`, Cycles, около 1 мин на Apple M4)

- **20 кадров VDB: 8, 16, 26, 36, 46, 54, 58, 62, 66, 70, 74, 77, 80, 83, 86, 89, 92, 95, 98, 100** (по 40 мс в игре). Огненный шар растёт за 5 кадров (8–46, 0–200 мс); тёмное «обсидиановое» облако с огненными просветами (54–70) — кадры 5–9, 200–400 мс, пока взрыв ещё непрозрачен; дальше дым густеет и тает вместе с прозрачностью узла (шаг по симуляции мельче — дым будто зависает). После 100-го облако упирается в край кадра. Первый вариант (8–100 через 4, 24 кадра) показывал тёмную фазу уже на угасании, и взрыв читался просто огненным.
- Камера **ортографическая, строго сверху** (`--elev 90`), ширина кадра 1,7 м (`--scale 1.7`), кадр 256×256, 24 сэмпла с шумоподавлением. Сбоку взрыв — «гриб», над полем он должен читаться круглым.
- Сверху облако вытянуто (≈1,5 : 1, ось под 55°): симуляция повёрнута на −55° вокруг вертикали и сжата по X до 0,72 (`--yaw -55 --squash 0.72`) — облако почти круглое (отношение осей 1,06–1,23).
- Материал: пламя — `flames / 4` на градиент B-spline 0 чёрный → 0,1 тёмно-красный → 0,3 красный → 0,6 `#ff8a3d` → 1 светло-оранжевый (1, 0,36, 0,08 линейный), сила свечения `flames × 0,05`; дым — `density × 6`, цвет — оттенок «обсидиана» `#1a1418` (лиловато-чёрный), альбедо по красному 0,18 (`--albedo 0.18`), мир — тусклый сливовый (0,11 0,09 0,12) силы 0,8, тёплая точечная лампа в сердце взрыва (60 Вт, оранжевая) подсвечивает дым изнутри.
- Прозрачный фон, EXR (линейный, альфа умножена) → PNG RGBA прямо в скрипте: огонь светит сильнее, чем закрывает фон, поэтому альфа = max(A, max(RGB)), цвет = RGB / альфа; яркость сжимается мягким коленом по каждому каналу (`--knee 0.6`), гамма sRGB. Жёсткое отсечение давало бело-жёлтый шар (вспышку), колено с сохранением оттенка — плоский оранжевый диск; колено по каналам оставляет рельеф пламени и не уходит в белое.

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup \
    --python blender/explosion_vdb.py -- \
    --vdb ~/vdb-src/ground-explosion/ground_explosion/ground_explosion_VDB --out <кадры>
```

(все остальные значения — по умолчанию в скрипте).

## Сборка (`tools/pack_strike.py`, Pillow + cwebp)

Альфа кадров не пересчитывается. Место взрыва — центр тяжести альфы первых 6 кадров; кадры обрезаются квадратом вокруг него (полуширина — наибольшее удаление облака по всем кадрам + 3 px), поэтому центр узла `.fx-bomb` — точка удара. Лист — **одна строка 20 кадров 256×256** (5120×256), `cwebp -q 74 -alpha_q 85 -m 6`, **317 КБ**. Поперечник облака в кадрах 5–9 — 0,8 кадра, поэтому узел шириной 4 клетки (`BOMB_CELLS` в `js/visuals-fx.js`): облако ложится на 3×3, дымные края заходят за них.

```bash
python3 tools/pack_strike.py <кадры> assets/fx/bomb.webp --json assets/fx/bomb.json
python3 tools/pack_strike.py --check     # 20 кадров 256x256, лист 5120x256, 317 КБ; выход 0
```

## В игре

- `.fx-strike.fx-bomb` в `#fx` (`css/fx.css`): кадры листает `steps(20, jump-none)` по `background-position` за `TIMING.strikeMs.bomb` = 800 мс. Появление, рост 0,8 → 1,06 и угасание — Web Animations (`opacity`, `transform`): за 50 мс проявляется, полная яркость до 45 % длительности (360 мс), к 85 % облако растаяло — новые камни падают в воронку с 310 мс, и плотный дым поверх них дольше выглядел бы грязной пеленой. Узел живёт 840 мс. Узел лежит над камнями, но под осколками и холстом с углями. Пробовали класть взрыв под камни (новые камни падают поверх дыма) — чище во время падения, но нужен второй слой эффектов; оставлен запасным вариантом.
- Угли — 18 частиц на canvas (`Fx.particles('ember')`): яркая точка с ореолом 0,2–0,32 клетки (мягкое пятно без ядра на золотых камнях не читалось), вылетают из облака во все стороны, тормозят, проседают и гаснут за 0,6–0,9 с, остывая от `#ffb15c` (ядро `#fff0c4`) к `#9a2e14`.
- «Спокойно»: углей 10, взрыв прозрачнее (× 0,6). Слабый компьютер: взрыв без углей. `prefers-reduced-motion`: ничего.
- Ни вспышки экрана, ни тряски поля.

## Молния, солнце, тотем (`tools/render_strikes.py`, образец 2)

Образец 2 (утверждён: «Да, берём» — молния, солнце, тотем; тотем в виде нефритовых лучей принят): `strikes/sample2.webm` (Chromium, 1366×768, ~15 с): молния по ряду и по столбцу, солнце, тотем на «Обычно» и солнце на «Спокойно». Запись и кадры — `tools/record-fx.js --scenario strikes`.

Процедурный рендер без внешних картинок (numpy из встроенного Python Blender): многооктавный шум со сдвигом координат (domain warp) для живого тела, ось с плавным дрожанием, тонкие разряды по шумовым нитям, запас яркости под цветовой градиент. Яркость запекается в альфу (альфа = яркость, цвет — по градиенту заданных цветов); рисуется обычным наложением — `mix-blend-mode` на слое `#fx` не работает: у него свой контекст наложения (`z-index`).

```bash
/Applications/Blender.app/Contents/Resources/5.2/python/bin/python3.13 tools/render_strikes.py assets/fx
```

Первый проход был пересвечен («белый лазер») и волна — плоская бледная полоса; во втором ядро сужено, потолок яркости снижен до светлого заданного цвета, тело вынесено в средние тона, волне дан непрерывный жгут во всю длину полосы.

## В игре (`Fx.strike`, `js/visuals-fx.js`)

- **Молния** `.fx-strike.fx-line` — две полосы от центра клетки в обе стороны вдоль `lineDir`: узел-окно (`overflow: hidden`) и внутри лист, выезжающий `translateX` (рисунок не сжимается, кончик впереди); конец листа лежит у края поля (лист масштабирован по ширине поля и прижат вправо). Скорость выезда — 18 мс на клетку, как расколы (`waveStepMs × 0,6`), а не 250 мс из плана: иначе камни разлетались бы раньше, чем до них дойдёт луч. Держится до 40 % из 700 мс и гаснет. В клетке — бирюзовое ядро.
- **Солнце** `.fx-ray` — узкие лучи `scaleX 0→1` к каждой цели своего цвета, луч доходит до камня ровно к его задержке; лучей не больше 16 — к ближним (дальние раскалываются без луча). В центре — золотое ядро (4 клетки) с медленным поворотом, гаснет к 900 мс.
- **Тотем** `.fx-wave` — те же полосы крестом, выезд 30 мс на клетку (`waveStepMs`), до 850 мс. В клетке — нефритовое ядро.
- `.fx-core`: лист `glow-cores.webp`, столбец — классом `fx-core-sun|line|wave`.
- «Спокойно»: все узлы × `beamAlpha` (0,6). Слабый компьютер: спрайты есть, частиц нет. `prefers-reduced-motion`: узлов удара нет. Ни вспышки экрана, ни тряски поля, белого кольца больше нет (`impactFx` убран, большие каскады просто раскалываются).
