## obsidian.webp — бесшовность
Codex дал 1254×1254 с трещинами, обрезанными по краям. Сделал бесшовным сам: взял 1024×1024, по каждой оси перекрёстное растворение (smoothstep, перекрытие 230 px) начала тайла с его продолжением — тайл периодичен. Затем 512×512 (LANCZOS). Проверка: склейка 2×2 с усилением яркости ×6/×8, стыков не видно; средний скачок через границу 0.60/0.71 против 0.55 между соседними пикселями. Трещины в 2×2 повторяются (видно только при усилении яркости).

## panel-frame.webp — `border-image`
Codex сгенерировал рамку с однородным меандром по сторонам и украшениями (заклёпка + квадратная нефритовая вставка) только в углах. Дальше пересобрал картинку: внешнее поле и внутренняя зона (обсидиан) прозрачны; углы взяты из исходника как есть, боковые полосы — один повторяющийся тайл (4 периода меандра, концы сведены растворением 50 px, поэтому `round` не даёт швов); в картинке нет лишнего, середина (центр) прозрачна. Нижняя кромка углов и тайлов взяты с запасом из прозрачного поля, чтобы Firefox не «подмешивал» соседнюю строку золота (был волосок на стыке тайлов).

`border-image-slice` (px картинки 418×355): **верх 58, право 83, низ 58, лево 89** (без `fill`).
Рекомендация: `border-image-repeat: round`. Рабочий пример (проверен в Firefox, `series-preview.html`):
```css
border: 18px solid transparent;           /* раскладка */
border-image: url(../assets/ui/panel-frame.webp) 58 83 58 89 / 18px 27px 18px 29px round;
background: url(../assets/ui/obsidian.webp) 0 0 / 256px;   /* заливка под рамкой, border-box */
```
Ширины 27/29 px по бокам больше раскладочных 18 px: углы с нефритом шире, чем полоса (масштаб 18/58 везде одинаков); лишние 8–11 px лежат на прозрачной внутренней полосе картинки и не мешают тексту.

## btn-plate.webp — `border-image ... fill`
Плита обсидиан, тонкая золотая кромка (после правки около 2.4% высоты; Codex дал 1.6%, утолщена копиями кольца, сдвинутыми внутрь на 4 px при полном размере), скруглённые углы, без свечения и меандра. Внутренность приглушена (множитель 0.5 вне золота), чтобы блики и трещины не спорили с текстом.

`border-image-slice`: **20** со всех сторон, с `fill`. Рекомендация: `border-image: url(../assets/ui/btn-plate.webp) 20 fill / 14px stretch; border: 14px solid transparent;` (кнопка 300×72: золото ≈ 3 px; при 56 px высоты ≈ 2.5 px).

## board-frame-gold.webp
Золотой меандр, квадратные нефритовые вставки в серединах сторон, заклёпки в углах. Центр и внешнее поле прозрачны. Толщина полосы ≈ **8.3 % ширины** (лево 8.3, право 8.1, верх 8.1, низ 8.4). Использовать как фон растянутым, как сейчас старая рамка (`styles.css:899`, `background: url(...) center / 100% 100%`), с внутренним отступом ≈ **8.4 %**; через `border-image` не резать — вставки в серединах сторон ломаются. Картинка почти квадратная (900×898).

## Огонь

- Первый вариант — своя симуляция Mantaflow (`blender/fire.py`) — отклонён: «огонь очень дешёвый… ощущение, что это игра из 90-х». Скрипт остался запасным путём.
- Утверждён: готовая симуляция **EmberGen «Small Camp Fire»** из бесплатного набора JangaFX — https://jangafx.com/software/embergen/download/free-vdb-animations/ (архив `SmallCampfireVDB.zip`, 200 кадров VDB, поля `flames`, `density`; лицензия **CC0 — Public Domain**, авторы просят упоминать «Created with EmberGen by JangaFX»). VDB в git нет.
- Рендер: `blender/fire_vdb.py -- --vdb <папка VDB> --out <кадры> --render 40-199 --center 0.02x-1.1 --scale 1.15 --size 448x384 --samples 64 --view Standard --glow 1.4 --range 1.6`. Светится только `flames`, дым выключен, градиент B-spline: 0 чёрный, 0.08 тёмно-красный, 0.25 красно-оранжевый, 0.5 оранжевый, 0.75 жёлто-оранжевый, 1 жёлто-белый; `flames / 1.6` на вход градиента; интерполяция объёма CUBIC. AgX отклонён: уводит пламя в розовый.
- Сборка: `tools/pack_fire.py <кадры> <лист> --loop 48 --fade 12 --start auto --crop --width 224 --q 76`. На образце начало цикла — 54-й кадр от начала рендера, кадр 224×196, лист 8×6 = 1792×1176, 681 КБ.
- Вспышка — кодом (рост, вторая копия листа поверх с `screen`, ускорение, искры), отдельного листа нет.

## Сборка

`python3 tools/pack_backdrop.py --land 1` (только Pillow) кладёт в `assets/backdrop/land1/`:

- `plate.webp` — плита как есть, q 86.
- `water-mask.webp` — где вода видна. Вырезка плиты x 20–170, y 0–905; яркость, размытая на 10 px, `(L−45)/40`, умноженная на синеву `(B−R+5)/30`, потом размытие 6 px и затухание сверху на 40 px, снизу на 60 px. Хранится в **альфа**-канале белой картинки WebP lossless: CSS `mask` по умолчанию берёт альфу, серая картинка без альфы ничего не маскирует.
- `water.webp` — плитка «струй». Кусок вырезки y 150–750, «высокие частоты» `(s − blur7(s))·2.2 + 8`, растяжение по вертикали ×1,3, бесшовность: последние 120 строк плавно переходят в первые 120, которые отбрасываются. Итог 150×660, плитка = 660/941 высоты плиты.
- `moon.webp` — 256×256, круглая альфа (суперсэмплинг ×4, отступ 1,5 px). Вшиты `brightness(.92)` и размытие (в пробнике CSS `blur(.6px)` шёл по диску около 100 px, на картинке 256 px это около 1,5 px). Непрозрачность 0,8 — в CSS.
- `clouds.webp` — вдвое меньше исходника, 1086×362. Альфа = `max(R,G,B)`, нормированная к 99,9-му процентилю, со степенью 0,8; цвет постоянный бледно-серо-голубой (190, 205, 225). (Пробник делил цвет на максимум канала; в плане решено иначе.)
- `backdrop.json` — размеры и геометрия воды; правда для CSS и JS.

Скрипт печатает размеры файлов (бюджет 450 КБ на все) и числа шва струй, и собирает лист проверки `backdrop/check.png` (маска, две копии плитки одна над другой, луна и облака на `#0d1b2e`).

Шов струй: стык «последняя → первая» строка сравнивается со средней разностью соседних строк. По всей плитке отношение 1,70, но там много гладких строк в зоне склейки; рядом со швом (±30 строк) — 1,12. На картинке шов не виден.
